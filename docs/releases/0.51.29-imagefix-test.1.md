# 0.51.29-imagefix-test.1 — Android 图片聊天内存修复

修复起因：Android 实机日志显示 Capacitor 文件接口处理约 40.5 MiB 的图片会话时触发 Java OutOfMemoryError；该会话将三张图片数据重复保存了三遍。先前隔离原文件只恢复了启动，本版处理新图片聊天的保存和读取问题。

- 图片原数据无损保存在当前 Vault 的插件会话目录 `sessions/media/`，相同数据按 SHA-256 去重，分块最多 512 KiB。JSONL 仅保留引用；重开会话时恢复并校验原数据，发送给模型的仍是原图。
- 会话列表逐个读取，不再并发读取全部历史文件。对旧大文件先检查大小，避免进入原生接口后导致应用进程崩溃。
- 图片分块缺失、内容冲突、写入失败时明确报错；不把失败保存视为成功。不会自动删除共享图片或原会话。
- 手机 OpenAI-compatible 请求在进入 requestUrl 前检查体积；整个请求（包括历史）超过 16 MiB 时提示分批或新建聊天，不静默压缩或删除图片。
- 单张原图继续最多 10 MiB。纯文本单条保存最多 1 MiB，JSONL 总量最多 4 MiB；达到容量会提示新建聊天，保留旧记录。

本次只改聊天图片存储、会话读取和手机请求保护。沿用手机现有 test.2 功能基线，不修改 COS、Memory、知识库工具、服务器或 Syncthing，不恢复已停止的 COS 项目。

旧超大会话仍保留备份，本版不会自动加载或迁移此前隔离的约 40.5 MiB 文件。更新后先新建聊天发送图片。备份/同步聊天数据时应保留整个 sessions 目录，包括 media 子目录；旧版不理解新的图片引用，不建议直接降级读取新图片聊天。

验证：两个回归检查在修复前失败；48 项定向单元检查通过，覆盖原数据还原、重复图片去重、损坏分块、失败保存、旧文件读取保护和模型请求保护。真实 Obsidian 1.15.0 移动界面仿真通过 1 项原图历史恢复显示检查。构建、类型和移动兼容检查随发布包核验。
