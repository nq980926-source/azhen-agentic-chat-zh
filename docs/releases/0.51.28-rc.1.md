# 阿斟日常照片正式候选版 0.51.28-rc.1

基线：0.51.28-photos-test.2，ba66bf0145646b5ed0821efe258efbd057e15582。

## 日常使用

首次在每台设备的照片设置中输入一次性配对码，系统自动保存此设备独立凭据，不需要查看、复制或发送 Token。

打开本地 Markdown 笔记，点击侧栏照片按钮，或使用“为当前笔记选择并保存照片”命令。选择原图，逐张勾选并确认上传。已 confirmed 的照片自动追加到批准时显示的目标笔记；不会覆盖正文。随后在 Android、Windows 的 Live Preview 或 Reading View 中显示照片。

每张最多 10 MiB（10485760 字节），每批最多 4 张、合计最多 40 MiB（41943040 字节）。拒绝超限，不压缩、不转码。PNG、JPEG、WebP、GIF 沿用现有支持范围。聊天图片入口也接受同样大小；仅保存照片不需要将照片先发送给 AI。图片理解还受模型供应商自己的限制，照片直存不依赖模型。

笔记只存 `azhen-photo://v1/<photoId>`。读取时自动换取短时授权并校验实际字节 SHA-256；签名 URL 不写入笔记、设置或任务记录。缓存只在本机内存，原图字节上限 40 MiB（浏览器解码内存另计）；按可见区域加载并释放离屏显示资源。

## 配置与恢复

配对码 10 分钟有效、只能使用一次，这只是首次设备连接的保护，不是照片使用窗口。设备长期凭据无固定到期时间，可单独撤销。后端只持久化摘要。设备凭据、本机启用状态及凭据引用使用 Obsidian SecretStorage / 本机存储，避免随 Vault 配置同步。其他设备需各自配对。

照片配对要求 Obsidian 1.11.5+，该版本加入了 SecretStorage 落盘加密；插件整体仍保留 1.11.4 最低版本，旧客户端不会因此失去本地聊天能力。依据：[Obsidian 1.11.5 官方说明](https://obsidian.md/changelog/2026-01-20-desktop-v1.11.5/)。

管理员在已部署的照片服务中运行 `deploy/manage.py pair`，仅在自己的管理终端看到配对码。不要把配对码、Token、COS 密钥或签名 URL 发到聊天。设备列表和单设备撤销使用现有服务账户运行 `photo_auth.device_admin list/revoke`，不删除照片。

上传结果不明时，同一回执的“重新选择并批准未完成照片”复用原任务，对账后才决定是否重传；每次仍需用户批准。不会自动重放未完成任务或删除孤立对象。已确认照片的笔记追加失败时保留稳定引用供恢复。

## 部署状态与边界

此候选版的源代码、构建和部署附件已准备；生产变更必须按 `PRODUCTION_CHANGE_REQUEST.md` 一次性批准后执行。发布候选版不等于生产服务已部署，不占用正式版 Latest。

正式新写入前缀为 `private-photos/v1/`。唯一已知隔离前缀只提供旧照片读取兼容，不用于正式上传。复用现有 Bucket、Region、CAM 身份、SDK、SQLite 元数据目录和 HTTPS 入口。

服务端正式配置 10 MiB / 4 / 40 MiB，日上传最多 100 张及 1 GiB、日读取授权最多 4 GiB；该日读取值是授权预留预算，不是 COS 计费硬封顶。原图直传 COS，照片 API 仍只接收小型 JSON，32 KiB 请求体限制不需要扩大为原图大小。

Knowledge MCP、阿斟 Memory、云端工作台、本地文件工具、财务工具和自动同步机制均未重新设计或改动。

## 验证与已知限制

自动验证聚焦新尺寸边界、原字节 MD5/SHA256、真实 SQLite 设备配对/撤销/限速、原生 Obsidian 界面和编辑预览。没有通过 Mock COS 回执冒充真实上传成功，也没有要求用户执行临时小图片测试。

Windows Origin 已在原生 Obsidian 1.15.0 观测为 `app://obsidian.md`；Android 采用用户已经实测的 `http://localhost`。生产 Nginx 和 Bucket CORS 的新增 Windows Origin 需要纳入生产批准。

Live Preview 支持插件生成的独立行照片引用；光标在引用行时显示可编辑的原文。行内引用仍由 Reading View 支持。Source Mode、代码围栏和 frontmatter 不渲染照片。

离线或未配对时文字仍可本地编辑，照片显示占位；没有新建磁盘照片缓存或 Syncthing 图片同步。元数据每日一致性备份保留最近 30 份，仍在现有主机；整机丢失的异地恢复依赖现有云主机快照/管理员异地备份。对象原图由私有 COS 保存。

服务端正式变更及真实日常使用效果尚待批准部署后确认。该限制不会转成一系列用户模拟验收步骤。
